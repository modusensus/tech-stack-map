## 三件套与盖房子类比

| 技术       | 类比     | 负责什么                       |
| ---------- | -------- | ------------------------------ |
| HTML       | 毛坯房   | 门在哪、窗在哪（结构和内容）   |
| CSS        | 装修     | 墙刷什么色、家具怎么摆（外观） |
| JavaScript | 水电电器 | 开关一按灯就亮（交互行为）     |

学习顺序照这个来：先 HTML → 再 CSS → 最后 JS。

## HTML 骨架

```html
<!DOCTYPE html>
<!-- 告诉浏览器：这是一份现代 HTML 文档，请用标准模式渲染 -->

<html lang="zh-CN">
<!-- 整个页面的根标签；lang 声明语言，方便浏览器和搜索引擎理解 -->

<head>
  <!-- "后台"区域：写给浏览器看的配置，不会显示在页面正文里 -->
  <meta charset="UTF-8">
  <!-- 声明编码为 UTF-8，中文才不会乱码 -->
  <title>页面标题</title>
  <!-- 显示在浏览器标签页上，也是搜索结果里的标题 -->
</head>

<body>
  <!-- "前台"区域：用户真正能看到的内容，全部写在这里 -->
  <h1>你好</h1>
  <p>一段文字</p>
</body>

</html>
```

**head vs body**：整栋房子里，`<head>` 是后台机房（游客看不到），`<body>` 是游客参观的展厅（看到的一切都在这）。

**踩坑连接**：Docker 那次 nginx 显示"鎴戠殑"乱码，就是因为 HTML 缺了 `<meta charset="UTF-8">` 这一行。

## 标签规则

- 标签几乎都是**成对出现**：`<p>` 开盒，`</p>` 关盒（斜杠 `/` = 关盒子的动作）
- 中间夹的内容 = 展示给用户看的
- 标签名小写

## 常用标签

```html
<h1>一级标题</h1>   <!-- 页面最大的字，一个页面一般只用一次 -->
<h2>二级标题</h2>   <!-- 比 h1 小一号 -->
<p>一个段落</p>     <!-- paragraph，浏览器会自动在段落前后留空隙 -->

<ul>                <!-- unordered list 无序列表 -->
  <li>列表项一</li>  <!-- list item -->
  <li>列表项二</li>
</ul>
```

## Markdown 与 HTML 对照

Markdown 是 HTML 的"速记版"，写完最终会被编译成 HTML。会 Markdown 的人学 HTML 有天然优势：

| Markdown           | HTML                       |
| ------------------ | -------------------------- |
| `# 大标题`       | `<h1>大标题</h1>`        |
| `## 小标题`      | `<h2>小标题</h2>`        |
| 直接写的段落       | `<p>段落</p>`            |
| `- 项目`         | `<ul><li>项目</li></ul>` |
| `*强调*`         | `<em>强调</em>`          |
| `**重要**`       | `<strong>重要</strong>`  |
| `[链接](url)`    | `<a href="url">链接</a>` |
| `![图](pic.jpg)` | `<img src="pic.jpg">`    |

## 家族树 — 层级结构

**核心规则只有一条：谁直接包着谁，谁就是谁爹。** 隔一层不算直系，判定关系不许跳级。

```html
<body>          <!-- 爷爷：直接包着的唯一孩子是 div -->
  <div>         <!-- 爸爸：上有 body，下有 h1 和 p -->
    <h1>...</h1>  <!-- 老大：爹是 div，爷爷是 body -->
    <p>...</p>    <!-- 老二：h1 和 p 同爹 → 兄弟 -->
  </div>
</body>
```

家谱图：

```
body（爷爷）
└── div（爸爸）
    ├── h1（老大）
    └── p（老二）
```

- 兄弟：同一个爹直接包着的两个元素（如 h2 和 ul 同在 body 下）
- 爷孙：隔一层（body 与 h1）
- 叔伯：爹的兄弟（h1 之于 li：li 的爹是 ul，h1 和 ul 是兄弟）

**重要性质**：往页面里塞一个 `<div>`，页面长相不变（透明盒），但家族关系全变——样式继承路径跟着变。CSS 的"遗传定律"（子元素继承父元素样式）就建立在这棵树上。

## div — 透明收纳盒

没有任何含义和样式，唯一用途是"把一堆东西装进一组"，类似展厅里的隔断。以后写 CSS 会大量使用。

## 属性初识 — href

属性 = 写在**开标签**里的附加信息，给机器看的指令；标签**中间**的内容才是给人看的。

```html
<a href="https://github.com/用户名">我的 GitHub</a>
<!-- a = anchor（锚点/链接）
     href = "点了之后跳去哪"
     中间文字 = 用户看到、能点的内容 -->
```

一个标签"内外有别"：`href="..."` 是属性（内含指令），文字是内容（外显信息）。

## 属性三件套 — 格式与规则

**属性 = 写在开标签里的"快递单"**：盒子外面的指令，给机器看；盒子里面装的货，才给人看。

```html
属性名="属性值"
href="https://..."     名字是 href，值是网址
lang="zh-CN"           名字是 lang，值是 zh-CN
charset="UTF-8"        名字是 charset，值是 UTF-8
```

三条铁律：

1. 只写在**开标签**里（`<a 属性在这>`），闭标签 `</a>` 里什么都不放
2. 格式永远是 `名字="值"`，等号两边别加空格
3. 值要用引号包住（单双都行，但别一边有一边没有）

**引号必须打吗**：规范上，值不含空格和特殊符号时省略引号也合法（`<div id=summary>` 浏览器接受）。但**永远建议打**——值里一旦有空格会被静默切断：`<img src=cute cat.jpg>` 中 src 只读到 "cute"，"cat.jpg" 被当成一个自创属性，图片裂了还不报错。引号是免费的保险。

**布尔属性彩蛋**：有一种属性可以没值，如 `<input disabled>`——出现即生效。见到再细讲。

**自闭合标签**：`<img src="cat.jpg">` 没有闭标签——因为盒子里根本没装货，快递单（去哪取图）本身就是全部。`<meta>` 也是这类。

**`<img>` 各部分用户看得到吗**：

| 代码部分          | 是什么             | 用户看得到吗 |
| ----------------- | ------------------ | ------------ |
| `img`           | 盒子类型（图片盒） | 看不到       |
| `src="cat.jpg"` | 快递单（去哪取图） | 看不到       |
| 渲染出的那张图    | 货物本身           | 看得到       |

对比 `<a>`：盒子里装了货（中间文字），所以文字可见 → 需要闭标签。

## alt — 图片的声音替身

```html
<img src="cat.jpg" alt="一只橘猫趴在键盘上睡觉">
<!-- src = 快递单：去哪取货；alt = 货箱上的说明卡：货是什么 -->
```

**给三种人看**：读屏软件的盲人用户（图对他们是"不存在"的，alt 是声音替身）、图挂掉时的兜底显示、搜索引擎理解图片内容（图片搜索全靠它）。

**两条规矩**（axe-core 的 `image-alt` 规则天天查）：

1. 每张图必须有 alt 属性——装饰性图片用空值 `alt=""`（="没信息量，请跳过"）。不写属性 = 犯规，写空值 = 合规
2. 别写"一张……的图片"——读屏念到 img 已会提示"图像"，直接描述内容即可

**功能性图片**：被 `<a>` 包着的 img = 可点击的图片，alt 必须写"这是什么 / 点了去哪"（如 `alt="Isabelle Rodriguez 的博主头像"`）。这类图 alt 缺失比普通图更严重——读屏用户会拿到一个"无名按钮"。

**体感记录**：见到没 alt 的图，"不存在但又处处存在"的难受感——这就是盲人用户的日常，a11y 的共情触发器。

**alt 的语言**：跟着页面的 `lang` 声明走，一页一语言。读屏软件靠 lang 声明挑语音引擎，alt 语言和声明不符会念出乱调。多语言站点 = 一个语言一个页面，各配各的翻译版 alt——alt 是内容的一部分，i18n 时也要翻译。

**与 SEO 的关系**：搜索引擎和读屏软件一样，都是"看不见渲染效果的机器"。语义化 HTML（title/h1/alt/lang）= 给机器递小抄，a11y 和 SEO 是同一枚硬币的两面。

## img 的尺寸 — width 与 height

```html
<img src="头像.jpg" alt="我的头像" width="200" height="200">
```

- `width` = 图片显示的宽度（像素），`height` = 高度
- 属性里的数字是**显示尺寸**，不是图片文件本身的真实大小（真实大小在文件里，靠 src 去取）
- 只写一个也行（浏览器按比例算另一个），但两个都写可以防"加载时页面跳动"——图片没加载完时先占好位

## id — 元素的学号

页面上有一堆长得一模一样的 `<div>`，要精确指出"改哪个盒"，就发学号。`id` = 元素的学号，**全页唯一**。

```html
<div id="introduction">
<!--  ↑ 属性名   ↑ 属性值：这个学号叫 "introduction" -->
```

写法和所有属性一样：`名字="值"`，放开标签里。CSS 和 JS 以后全靠学号找人。

**Codecademy 卡点复盘**：提示框里的 `<div id="summary">` 只是**格式示范**（像老师黑板写"姓名：张三"教你格式），自己交表不能也填"张三"——照抄示范值会报错，要按题目要求填指定的值。

## 行内 vs 块级 — span 与 div

|      | `<div>`                                         | `<span>`                                       |
| ---- | ------------------------------------------------- | ------------------------------------------------ |
| 类比 | **纸箱/收纳盒**                             | **荧光笔**                                 |
| 占地 | 块级（block）：独占一整行，前后内容被挤到上下两行 | 行内（inline）：只圈住自己那几个字，排版纹丝不动 |
| 用途 | 把大块内容装箱分组                                | 给行内一小段内容做记号                           |

选型口诀：想**切开一块一块的**用 div；要在**同一行里挑一小段**用 span。

- `<a>` 链接也是行内的——链接文字和前后文字同处一行，荧光笔一伙
- 两者都透明无样式，单独放上去页面不变，意义是"做记号"给 CSS 精准下手

**亲手实验**（`01-html/span-vs-div.html`）：在句子中间插 div → 一句话撕成三行；插 span → 整句还是一行。亲眼见证 > 背诵。

**em vs span 辨析**：

|          | `<em>`                       | `<span>`                |
| -------- | ------------------------------ | ------------------------- |
| 出生自带 | 含义（强调）+ 默认样式（斜体） | 什么都没有，纯透明        |
| 类比     | 出厂自带墨水的荧光笔           | 空笔杆，要自己灌墨（CSS） |

选型口诀：表达"语气上要强调"用 em（语义化）；只是"做记号等 CSS/JS 来处理"用 span（中性，不擅自解读意图）。

## br 与 ol — 换行和有序列表

**`<br>` = 同段内强行断行**（break），空盒子标签（无闭标签）。区别：`<p>` 是另起一段（有空隙），`<br>` 是同段内紧挨着换行（诗歌、歌词、地址专用）。**禁止拿 br 当排版工具**（连打几个制造空隙是 CSS 的活）。

Markdown 对应：行尾打两个空格（或行尾 `\`）= `<br>`；空一行另起段 = `<p>`。这解释了"Markdown 按一次回车渲染出来不换行"——单个回车只是软换行。

**`<ol>` = 有序列表**：知识从 ul 直接平移，唯一区别是圆点变数字。选型口诀：调换顺序会出问题的用 ol（步骤、排行榜），无所谓的用 ul（购物清单）。

## video — 视频盒

```html
<video src="cat.mp4" controls>
  你的浏览器不支持视频  <!-- fallback 兜底内容：给老浏览器留的路 -->
</video>
```

- **双标签**（和 img 不同）——盒子里装了货（fallback 文字）
- **布尔属性正式出场**：`controls` 无值、出现即生效；同类 `autoplay` / `muted` / `loop`
- **a11y 红线**：`autoplay` + 有声音 = 公敌（WCAG：自动播超 3 秒必须可暂停）。实践口诀：**要 autoplay 就必须配 muted**
- 与 img 的关键区别：img 靠 alt 兜底就够；video 的 fallback 是唯一能自己写的救命稻草，几乎总要写

## href 三种地址类型

`href` 的值可以是三种"地址"，对照自己页面里的实例：

| 类型     | 写法                   | 去哪                                         |
| -------- | ---------------------- | -------------------------------------------- |
| 外部网址 | `href="https://..."` | 跳去别的网站                                 |
| 页内锚点 | `href="#学号"`       | 本页滚到`id="学号"` 的位置（学号见 id 篇） |
| 相对路径 | `href="文件名"`      | 本地文件，从"当前文件"出发找路               |

**相对路径的哲学**：不写域名，只写"从我这个文件出发怎么走"。同目录 = 直接写文件名；子文件夹里 = `文件夹名/文件名`。类比：绝对地址像快递单（完整地址），相对地址像"从我家出门左转就到了"。

## target — 在哪个窗口打开

`target` 决定链接在哪个"标签页"里打开，两个常用值：

| 值         | 效果                                         | 类比             |
| ---------- | -------------------------------------------- | ---------------- |
| `_self`  | 当前标签页跳走（**默认**，不写就是它） | 同一条路继续开车 |
| `_blank` | 新开标签页，原页面保留                       | 另叫一辆车并行   |

```html
<a href="url" target="_self">当前页打开（默认值）</a>
<a href="url" target="_blank">新标签页打开</a>
```

## 外链安全 — target 与 noopener

```html
<a href="..." target="_blank" rel="noopener noreferrer">我的博客</a>
```

- **反向操纵**（tabnabbing 钓鱼）：`_blank` 新开的页面能通过 `window.opener` 暗门反向改写你的老标签页——换成一模一样的假登录页偷密码
- **固定搭档口诀**：用了 `_blank` 就必须配 `rel="noopener noreferrer"`，像安全带的带扣，缺一半都不算写完
- `rel="noopener"`：焊死暗门；`noreferrer` 再加一层：新页面拿不到来路信息（注意：商业站统计工具反而想要来路，属性跟着需求走）
- 第一次摸到**前端安全**的边：浏览器给了能力，就要检查能力有没有被滥用——a11y 和安全是同一思维的两个方向

## 任何元素都能变链接 — 包裹法

"链接 = 点击文字"只是最朴素的形态。`<a>` 是万能相框：**中间放什么，什么就变成可点击区域**。

```html
<a href="https://www.modusensus.space" target="_blank" rel="noopener noreferrer">
  <img src="头像.jpg" alt="我的头像">
  <!-- 中间从文字换成图片 → 整张图变成点击区域 -->
</a>
```

- 核心姿势：把目标元素**裹进** `<a>` 开闭标签中间（开 `<a>` → 放内容 → 关 `</a>`）
- 可放：文字、图片，甚至一整个 `<div>`（整块卡片可点击）
- 一句话记忆：**"点击什么打开链接"取决于 `<a>` 肚子里装了什么**

## 缩进与注释 — 写给人看的两件套

**缩进（与父元素的关系）**：缩进不是浏览器规则，是人定的**家谱图**——子元素比爹多缩进一层，兄弟缩进相同。血缘（谁包谁）真实存在，缩进只是画给你看的连线。浏览器不认缩进（见"空白压缩"），但人眼靠它秒读家族树。

**30 秒检查法**：`</xxx>` 的缩进必须和它对应的 `<xxx>` 一模一样。

**注释**：给未来人类的留言条，浏览器直接跳过。

```html
<!-- 这是 HTML 注释：页面不显示 -->
<p>这段会显示</p>

<!-- 多行注释
     随便写几行
     都行 -->
```

对照 Python：

|      | HTML                  | Python          |
| ---- | --------------------- | --------------- |
| 记号 | `<!-- 内容 -->`     | `# 内容`      |
| 多行 | 一个`<!-- -->` 搞定 | 每行都要写`#` |

**临时开关技巧**：用 `<!-- -->` 包住一段代码 = 让浏览器忽略它（盖块布），调试时临时"删掉"某块内容很方便。

**注释也跟随缩进**：注释像贴在代码上的便签条，要贴在正确的辈分上——**注释缩进 = 它旁边那块代码的缩进**。乱缩进会让人眼误读"这条注释在说明谁"。写在代码上方、与之同层是最好习惯；写在闭标签后面（家谱图边边上）不推荐。

## 表格 — table 家族

**四个标签，一个都不能少**：

| 标签 | 全称 | 作用 | 类比 |
|---|---|---|---|
| `<table>` | table | 表格容器 | 买一张空桌 |
| `<tr>` | table row | 一行 | 桌上一横排 |
| `<th>` | table header | **表头**格（加粗居中） | 每列/每行的标题 |
| `<td>` | table data | **数据**格 | 装具体数据的格子 |

结构规律：**桌子里放行（tr），行里放格（th/td）**。每行列数必须一致，不然格子错位。

```html
<table>
  <tr>
    <th>科目</th>      <!-- 表头行：全用 th -->
    <th>时间</th>
  </tr>
  <tr>
    <td>编程</td>       <!-- 数据行：普通内容用 td -->
    <td>3 小时</td>
  </tr>
</table>
```

**关键事实：浏览器默认渲染"无形表格"**——没有边框，只是格子对齐。画边框有"三代写法"：

| 写法 | 是什么 | 地位 |
|---|---|---|
| `<table border="1">` | HTML 老属性（legacy） | 老古董，能用但已淘汰（浏览器为兼容老网页还认它） |
| `<table style="border: 1px solid black;">` | 塞进 HTML 里的 CSS | 过渡方案（HTML 阶段临时用） |
| 正式 CSS（选择器 + border） | 纯 CSS | 现代正规军（下一站学） |

**识别口诀**：看到 `border="1"` 别慌，是老式写法，认得就行；自己写优先用 style 或等 CSS。判断标准：老网页爱用 `border="1"`，现代代码不用。Codecademy 为快速展示效果会用老写法，但正规教学会引导到 CSS。

## scope — 表头管谁

`scope` 是 **`<th>` 的专属属性**（只能用在 th 上），声明这个标题管的是列还是行：

```html
<tr>
  <th scope="col">科目</th>    <!-- 竖着管整列 -->
  <th scope="col">时间</th>
</tr>
<tr>
  <th scope="row">编程</th>    <!-- 横着管整行 -->
  <td>3 小时</td>
</tr>
```

- `scope="col"` = "我是这一列的标题，往下的格子归我"
- `scope="row"` = "我是这一行的标题，往右的格子归我"
- **为什么重要**（a11y）：读屏软件一格一格念表格，没有 scope 时盲人用户听到 `3 小时` 不知道属于谁——像念成绩单只报分数不报科目。scope 让上下文不丢
- 行首的时间/姓名类"行标题"格，要写成 `<th scope="row">` 而不是 `<td>`

## HTTP 请求 — 浏览器与服务器的对话

**HTTP（HyperText Transfer Protocol）= 浏览器和服务器之间的"说话规矩"。HTTP 请求 = 浏览器递给服务器的一句话："我想要什么"。** 类比：去餐厅点餐，你每说一句话就是一个请求。

**请求类型（HTTP 方法）**：

| 方法 | 意思 | 餐厅类比 | 啥时候遇到 |
|---|---|---|---|
| **GET** | **拿**数据（只读） | "我要看菜单" | 打开网页、点链接、搜索——90% 是它 |
| **POST** | **送**数据（写入） | "我下单" | 提交表单、登录、发评论 |
| PUT | 整体更新 | "整道菜换新的" | 改资料（整份替换） |
| PATCH | 局部更新 | "少放点盐" | 改个别字段 |
| DELETE | 删除 | "撤掉这道菜" | 删帖子 |

**判别口诀**："看一下"是 GET，"交上去"是 POST。`<a>` 链接点击 = 发 GET 请求（网址本身是话术）。

## form — 网页的点餐单

`<form>` = 收集用户输入、打包发给服务器的**填表区**。类比点餐单：`<input>` = 空格，用户填的内容 = 写的字，提交按钮 = 交给服务员。

```html
<form action="https://example.com/login" method="POST">
  <!-- action = 数据送到哪（收件地址）；method = GET 还是 POST（快递方式） -->
  <label for="username">用户名：</label>
  <input type="text" id="username" name="username">
  <input type="password" id="password" name="password">
  <button type="submit">登录</button>
</form>
```

- `action` = 数据发去哪；`method` = GET（拼进网址，适合搜索）或 POST（藏请求肚子里，适合密码/注册）
- **每个 input 配 label** = a11y 硬规矩（盲人靠它知道空格是干嘛的，axe 的 `label` 规则查这个）
- 知识链打通：`<a>` = GET 请求 → `<form>` = 更正式的 GET/POST。**网页交互的本质 = HTML 元素触发 HTTP 请求**
- `<input>` 是"布尔属性"家族常客（`disabled` 那种）

## 浏览器 vs Python 的性格差异

|              | Python                  | 浏览器（HTML）                       |
| ------------ | ----------------------- | ------------------------------------ |
| 遇到语法错误 | 当场罢工（SyntaxError） | 自作主张猜你意图，硬着头皮渲染       |
| 出错表现     | 明确报错                | **不报错**，页面"看起来有点怪" |

陷阱：HTML 写错了不报错（比如多余的 `</li>` 会被默默忽略），所以不能靠"有没有报错"判断对错，要靠规范自觉 + 检查工具。

**为什么 HTML 这么宽容？当年故意设计的。** 互联网早期，网页给全世界人看——漏个标签就白屏的话用户只会骂网站，于是浏览器被设计成"尽力而为"：猜意图、宁可显示个大概也不给红字。Python 哲学相反：宁可当场罢工（SyntaxError 精确到行号）也不带错误跑。宽容是甜蜜的，也是陷阱的来源。

## 常见误区

- **多余的关闭标签**：开了 3 个 `<li>` 关了 4 个 `</li>`——浏览器不报错但代码是错的
- **提前封顶**：`</html>` 写在了 `<body>` 前面——body 被关在房子外，家谱断裂。正确顺序：`html 开 → head → body → html 关（永远最后）`
- **关系判定跳级**：h1 和 li 同在 body 里 ≠ 兄弟（li 的爹是 ul，中间隔了两层）
- **head 和 body 混淆**：想在页面上显示的内容必须写在 `<body>` 里
- **p 里塞 div**：不合法嵌套，浏览器会偷偷"提前关箱"把段落硬拆成几段——又见宽容陷阱
- **省略属性引号**：值含空格时被静默切断，后半截被浏览器当成自创属性——宽容陷阱再次现身
- **href 无引号 + 空值**：`<a href=my page.html>` 中 href 只读到 "my"，page.html 被当成自创属性——点击跳转到不存在的 `my` 页
- **Codecademy 中文课件错位**：正文讲 `<span>` 代码却是 `<h1>/<p>` 时，以代码为准
- **scope 装错标签**：把 `scope="row"` 写在 `<td>` 上 = 白写——scope 是 `<th>` 的专属属性，读屏会无视。正确姿势：标签换成 `<th>` + 加 `scope`，两个动作缺一不可
