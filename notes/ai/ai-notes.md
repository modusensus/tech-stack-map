## Phase 1：数学地基

### 向量与矩阵 — 从一串数字到变形机器

**正式定义**

- **向量（vector）**：n 维向量 `a = (a₁, a₂, …, aₙ)` 是 **ℝⁿ 空间中的一个元素**。
  它同时有两重身份：一个**点**（位置），和从原点出发的一支**箭**（方向）。
  - 维数（dimension）= 分量的个数
  - 模 / 长度（magnitude / norm）：`‖a‖ = √(a₁² + a₂² + … + aₙ²)`
- **矩阵（matrix）**：m×n 矩阵是一个 **m 行 n 列**的数表，形状记作 shape = (m, n)。
  它的数学身份是**线性变换**——一个把向量映射成向量的函数。
- **嵌入（embedding）**：把离散对象（词、图、用户）映射成连续向量的表示。
  "一个字 → 768 个数"里的那 768 个数，就是这个字的 embedding。

**它是干嘛用的（一句话）**

- 向量的模：算这根箭有多长
- 矩阵：把输入向量变换成输出向量
- **神经网络的一层 = 输入向量 × 权重矩阵 + 偏置 = 输出向量**

**趣味类比回顾（仅辅助记忆）**

- 向量 ≈ 地图上的一个坐标点 `(经度, 纬度)`
- 矩阵 ≈ 一台变形机器（旋转 / 缩放 / 拉伸 / 投影）
- 神经网络的一层 ≈ 洗衣机：进脏衣服（输入向量），出干净衣服（输出向量），滚筒就是矩阵

**避坑提醒**

- ⚠️ **分量的顺序是有意义的**：`[3, 5]` 与 `[5, 3]` 不是同一个点。
  每个位置代表什么，取决于**人为的定义**，换数据集含义就变。
- ⚠️ 向量本身不自带含义，含义是**规定的**。看论文时必须先找它的定义。
- ⚠️ 单行的 `[3, 2]` 是向量，不是矩阵。矩阵必须是"多行多列"的表。

### 读 `vectors.py` 前要认识的 Python 词

**这个文件是什么**

`stage-05-ai-tools/01-math-foundations/vectors.py` 不是工具、不是项目，是一个**练习文件**。
目的只有一个：把"向量""矩阵"这些数学概念，写成**能真的跑起来**的 Python 代码，
让"点积 = 对应位置相乘再相加"这句话可以被亲眼验证。

文件结构：

| 部分 | 内容 | 对应本课哪一块 |
| --- | --- | --- |
| `class Vector` | 向量及其运算 | 第 1~4 块 |
| `class Matrix` | 矩阵 = 线性变换 | 第 5 块 |
| 最底下 `if __name__ == "__main__":` | 演示区 | 直接跑就有输出 |

**五个词**

| 词 | 一句话 |
| --- | --- |
| **类**（class） | 把"一种东西"和"它的做法"打包在一起。`class Vector:` = 我要定义"向量"这种东西 |
| **实例**（instance） | 用这个定义真正造出来的一个具体对象。`Vector([1, 2, 3])` 造出的就是一个实例 |
| **`self`** | 实例自己。`self.components` 读作"我自己的 components" |
| **`__init__`** | 造一个新实例时**自动跑一遍**的那段代码 = "出生时要做的事" |
| **魔法方法** | 名字前后都是双下划线的函数，由 Python 在特定时刻自动调用。`__add__` 对应 `+`，`__mul__` 对应 `*`，`__repr__` 对应 `print` |

**`components` 和 `dim` 分别是什么**

- `components`：那个装着数字的列表本身。它不是 Python 的特殊词，是**自己起的名字**
  （component = 分量）。`Vector([1, 2, 3])` 里，`components` 就是 `[1, 2, 3]`。
- `dim`：dimension 的缩写，**存的就是维数**（有几个分量）。
  `self.dim = len(self.components)` 就是在数个数。
  单独存一份是为了"出生时数一次，以后直接查"，不必每次重新数。
- `self.components = list(components)` 里的 `list()` 是**复制一份**。
  不复制的话，外面改了原列表，这个向量会被悄悄改掉。

**避坑提醒**

- ⚠️ **`__init__` 永远不会手写调用**。你只写 `Vector([1, 2, 3])`，
  不去写 `v.__init__(...)`。双下划线是 Python 的约定，表示"这个名字归 Python 用"。
- ⚠️ **`zip` 静默截断**：两个长度不同的列表被 `zip` 配对时，按**短的那边**截断，
  而且**不报错**。所以 `Vector([1,2,3]) + Vector([4,5])` 会安静地返回
  `Vector([5, 7])`，维数从 3 变成 2，你还以为算对了。
  这类"不报错的错"是 AI 代码里最难查的 bug。
- ⚠️ **`x ** 0.5` 就是开平方**。`magnitude()` 里 `sum(x**2 for x in ...) ** 0.5`
  就是勾股定理，没有别的花样。
- ⚠️ **列表推导式 `[a + b for a, b in ...]` 会造一个新列表**，原对象不会被改动。
  所以 `a + b` 不会污染 `a` 或 `b`。

### 点积 — 量两个方向的相似度

**正式定义**

给定同维向量 `a = (a₁, …, aₙ)`、`b = (b₁, …, bₙ)`，点积为：

```
a · b = Σᵢ₌₁ⁿ aᵢbᵢ = a₁b₁ + a₂b₂ + … + aₙbₙ
```

即：**对应位置相乘，再全部加起来**，结果是**一个标量**（scalar，单个数字），不是向量。

判定三档：

| 点积 | 几何含义 | 人话 |
| --- | --- | --- |
| `a · b > 0` | 夹角 < 90° | 方向基本一致（相似） |
| `a · b = 0` | 垂直（正交） | 完全无关 |
| `a · b < 0` | 夹角 > 90° | 方向相反（不相似） |

**余弦相似度（cosine similarity）** —— 把长度除掉，只看方向：

```
cos(a, b) = (a · b) / (‖a‖ × ‖b‖)
```

范围固定在 −1 到 1 之间，所以比裸点积更适合做"像不像"的打分。
RAG、语义检索、记忆系统里算的"相似度"，通常就是这个。

**例子**

```
a = [1, 2, 3]
b = [4, 5, 6]

a · b = 1×4 + 2×5 + 3×6
      = 4 + 10 + 18
      = 32
```

**趣味类比回顾（仅辅助记忆）**

两个人给同一份菜单 `[麻, 辣, 甜]` 打分，点积越大口味越像。
点积像"三观契合度测试"：同向得高分，反着来得负分。

**避坑提醒**

- ⚠️ 两个向量的**维度必须相同**才能算点积，维度不同是"未定义"，不是算不出来
- ⚠️ 结果是**一个标量**，不是向量——最容易记混的地方
- ⚠️ 别跟**逐元素相乘（Hadamard 积）**搞混：
  `[1,2,3] ⊙ [4,5,6] = [4,10,18]`（还是向量）；点积 `= 32`（一个数）
- ⚠️ 点积**不是距离**。距离是越小越像，点积是越大越像
- ⚠️ 点积会被向量**长度**带偏：一根很长的箭方向不太对，点积也可能很大。
  所以只看方向时要用**余弦相似度**

### 余弦相似度 — 分母是哪来的、什么时候会失灵

**分母是哪来的（推导源头）**

起点是那个毛病：**点积会被长度污染**。

```
[1,0] · [100,0] = 100
```

方向完全一样，点积却大得吓人——全部来自"对方很长"。要量"方向像不像"，
就必须把长度这个干扰项除掉：

```
cos(a, b) = (a · b) / (‖a‖ × ‖b‖)
```

分母 `‖a‖ × ‖b‖` 就是"污染量"：两边各自有多长，乘起来就是这份干扰的大小。
除掉它，效果等价于**先把两根箭都缩到长度 1，再算点积**。

范围永远卡在 −1 到 1，因为 cos 这个函数本身就出不去：

| cos 值 | 夹角 | 含义 |
| --- | --- | --- |
| 1 | 0° | 完全同向 |
| 0 | 90° | 垂直，毫无关系 |
| −1 | 180° | 完全反向 |

**什么时候会失灵**

1. **任一边是零向量** → 分母为 0，**直接除零报错**（不是返回 0）。
   空输入、被过滤／截断的样本、padding 都可能造出全零向量。
2. **看不见"大小"**：`[1,1]` 和 `[100,100]` 的余弦相似度是 **1**（完全一样），
   但它们差了 100 倍。如果"强度"本身有含义（评分高低、出现次数、置信度），
   余弦会把这份信息直接抹掉——这时该用点积或欧氏距离。
3. **绝对值不可信（真实 embedding 的方向会"扎堆"）**：真实 embedding 的向量并不是
   均匀撒满整个空间的，而是都朝大致相同的方向挤在一个很窄的锥里
   （术语：**各向异性 anisotropy**）。夹角本来就小，余弦自然普遍偏高——
   随便挑两句毫不相干的话，余弦也可能有 0.6~0.8。所以 0.7 说明不了什么，
   它可能只是"平均水平"。

   | 说法 | 对不对 |
   | --- | --- |
   | "维度一高，余弦就普遍偏大" | ❌ **错**。真正均匀随机的高维向量之间，余弦反而趋近 **0**（维度越高越挤在 0 附近） |
   | "真实 embedding 的向量方向扎堆，所以余弦普遍偏高" | ✅ 对，这才是真正的原因 |

   - 结论：**看排序靠谱，看绝对值不靠谱**。想知道某个值算不算高，先算一批随机配对的
     平均相似度当**基线**，再看它比基线高出多少。
   - 另：当所有分量都是非负数时（很多词频 / 计数向量），余弦只会在 0~1，不会出现负值。

**避坑提醒**

- ⚠️ 分母是两边长度**相乘**，不是相加，也不是分量平方和
- ⚠️ 余弦相似度**不是距离**，它是"越像越大"；距离是"越像越小"（常用 `1 − cos` 换算）
- ⚠️ 别把 `cos = 0.8` 直接读成"很相关"——先看这个模型的**基线**是多少，再判断
- ⚠️ 零向量时的表现是**崩溃报错**，不是安静返回 0——工程代码必须显式加保护

### 零向量 — 唯一没有方向的向量

**正式定义**

所有分量都是 0 的向量，记作 `0`。例如 `[0, 0]`（2 维）、`[0, 0, 0]`（3 维）。

**它到底算不算向量：算。**
判定标准只有一个——"是不是一串有序的数字"。`[0, 0]` 有两个数字，所以它是一个 **2 维向量**，
数字等于 0 不影响它的身份。

**它特殊在哪**

| 性质 | 说明 |
| --- | --- |
| 长度 | `√(0² + 0²) = 0`，它是**唯一**长度为 0 的向量（只有全 0，平方和才是 0） |
| 方向 | **没有方向**。别的向量是从原点射出的一支箭，它是站在原点不动，不动就谈不上朝哪 |
| 点积 | 与任何向量点积恒为 0 —— 但这**不是垂直**，是"方向根本没得谈" |
| 余弦相似度 | 分母 = `‖a‖ × 0 = 0` → **除零报错** |
| 归一化 | 每个分量除以 0 → 同样报错 |
| 线性无关 | 任何**包含零向量**的向量组必然**线性相关**（它没贡献任何新方向，是多余的） |

**为什么 AI 里要当心**

如果某个 embedding 恰好是全零向量（空输入、被过滤的样本、padding），
拿它去算相似度，程序会**当场崩溃**，而不是返回一个"不相似"。
工程上的做法是显式规定：**长度为 0 时，相似度定义为 0**。

对应到自己的代码：[vectors.py](file:///d:/python-study-map/tech-stack-map/stage-05-ai-tools/01-math-foundations/vectors.py#L123-L134)
里的 `cosine_similarity` 和 `normalize`，都**默认了长度一定不为 0**，没做这个保护。

**避坑提醒**

- ⚠️ 一句话记住它：**零向量是"向量"，但不是"方向"**
- ⚠️ 别把 `a · 0 = 0` 读成"a 和 0 垂直"——垂直的前提是两边都有方向
- ⚠️ 只有一个向量的长度可能为 0，就是零向量自己；不必担心"别的短向量也除零"

### 线性 / 线性组合 / 线性无关 — 正式定义

**正式定义**

**① 线性映射（linear map）**

设 `f: V → W` 是向量空间之间的映射。若对任意向量 `x, y` 和任意标量 `α`，满足：

| 性质 | 名称 | 式子 |
| --- | --- | --- |
| 1 | **可加性**（additivity） | `f(x + y) = f(x) + f(y)` |
| 2 | **齐次性**（homogeneity） | `f(αx) = α·f(x)` |

则称 `f` 是**线性**的。两条合起来等价于：

```
f(αx + βy) = α·f(x) + β·f(y)
```

即：**线性映射保持线性组合。**

推论：线性映射必然满足 `f(0) = 0`。（因为 `f(0) = f(0·x) = 0·f(x) = 0`）

**② 线性组合（linear combination）**

给定向量 `v₁, …, vₖ` 和标量 `c₁, …, cₖ`，形如

```
c₁v₁ + c₂v₂ + … + cₖvₖ
```

的向量称为这些向量的一个**线性组合**，`cᵢ` 称为**系数（coefficient）**。

所有线性组合构成的集合叫**张成（span）**，记作 `span{v₁, …, vₖ}`。

**③ 线性无关（linear independence）**

若方程

```
c₁v₁ + c₂v₂ + … + cₖvₖ = 0
```

**只有唯一解** `c₁ = c₂ = … = cₖ = 0`（称为平凡解），则称 `v₁, …, vₖ` **线性无关**。

若存在**不全为零**的系数使该式成立，则称**线性相关**。

**④ 矩阵乘法是线性的**

矩阵-向量乘法 `x ↦ Ax` 就是一个线性映射，所以它满足可加性与齐次性。

**趣味类比回顾（仅辅助记忆）**

- 线性 ≈ 买菜按斤计价（5 元/斤：1 斤 5 元，3 斤 15 元，两条规矩都满足）
- 非线性 ≈ 奶茶"第二杯半价"（量翻倍，钱没翻倍 → 违反齐次性）
- 线性组合 ≈ 可乐 + 雪碧调"可碧"（各按比例倒，混成一杯）
- 线性无关 ≈ 几种原浆互不替代；线性相关 ≈ 有一瓶是兑出来的废话

**避坑提醒**

- ⚠️ **"线性"≠"直线"**。中文翻译害人，它说的是"满足可加性 + 齐次性"，跟画不画直线无关
- ⚠️ **"线性无关"≠"互不相关"**。它是"没有一根是多余的"，不是"它们互不认识"
- ⚠️ **"线性相关"≠"因果关系"**。它只是"其中一根能由其他几根线性组合出来"
- ⚠️ 为什么神经网络必须加**激活函数**？因为矩阵乘法是线性的，纯线性层叠 100 层
  仍等价于 1 层；必须插入一个非线性函数，深度才有意义
- ⚠️ 遇到看不懂的段落，先回头查**有没有没解释过的名词**。90% 的"看不懂"卡在某个被跳过的词上

### 秩 — 了解级，本课不深究

**正式定义**

矩阵 `A` 的**秩（rank）** = `A` 的列向量组中，**极大线性无关组**所含向量的个数
（等于行向量组的极大线性无关组个数）。

```
rank(A) ≤ min(m, n)
```

`rank = min(m, n)` 称**满秩**；否则称**秩亏（rank-deficient）**。

**为什么 AI 关心它（了解即可）**

| 情况 | 对机器学习意味着什么 |
| --- | --- |
| 满秩 | 特征无冗余，最小二乘解唯一 |
| 秩亏 | 特征冗余（多重共线性），权重有无穷多组解，需要正则化 |
| 秩 = 1 | 所有数据落在一条直线上 |
| 接近秩亏 | 矩阵病态，输入微小噪声导致输出剧烈变化 |

秩亏的三个后果：解不唯一（或无解）、变换中信息丢失、矩阵**不可逆**。

**趣味类比回顾（仅辅助记忆）**

秩 ≈ 一个矩阵"真正装了几维有用信息"。3×3 但秩 = 2，相当于把立体压成一张纸。

**避坑提醒**

- ⚠️ 秩**不是**矩阵里非零元素的个数，别按数数理解
- ⚠️ 本课只要求"知道有这个概念"，**不要求会算**。Phase 3 讲神经网络时会再用到

### 超参数 vs 参数 — 菜谱与手感

**核心要点**

|                  | 谁定的             | 什么时候定                 | 例子                                     |
| ---------------- | ------------------ | -------------------------- | ---------------------------------------- |
| **超参数** | **人**       | 训练**开始前**       | 树的数量、学习率、批大小                 |
| **参数**   | **模型自己** | 训练**过程中**学会的 | 分裂阈值、叶子节点的预测值、神经网络权重 |

**趣味类比回顾**

- **超参数 = 你给的菜谱**：开火前就写好了"放几棵树、火开多大"
- **参数 = 厨师练出来的手感**：炒的过程中自己掌握的咸淡、火候

菜谱是你决定的；手感是厨师自己长出来的。这就是两者的分界线。

**避坑提醒**

- 判断口诀：**"要提前调的就是超参数，训练完自动有的就是参数"**
- 随机森林的"树的数量"是超参数（你定的）；"每棵树的分裂阈值"是参数（模型学的）——
  考试和面试最爱考这一对

## Phase 7：Transformer 深入

### LoRA — 贴便利贴式的微调

**核心要点**

微调大语言模型时，LoRA 的做法是：

- **冻结**基础模型的全部原始权重（一个字都不改）
- 只训练一小块新增的**低秩适配矩阵**

结果是**改动成本极低**，但模型能适配新任务。

**趣味类比回顾**

不是把整本书**重新印一遍**，而是在书上**贴几张便利贴**做修改。

书还是那本书（基础模型不动），便利贴很薄很少（低秩适配器），
但翻到对应页面时，读者看到的就是修改后的内容。

**避坑提醒**

- LoRA 让微调**更省资源**（省显存、省时间），**不是**让模型变大
- 最容易选错的反向答案：**"复制模型层来提升适应能力"**——这会让模型翻倍变大，
  跟 LoRA 的目的完全相反
- 记住一个词就够了：**冻结（freeze）**。看见"基础模型权重保持冻结"基本就是它
